# Phase 6.1: 2D FOV Collision & Occlusion (Map Mode)

**Context:** Extends Phase 6 (camera system) with 2D collision/occlusion logic for camera FOV wedges in map/editor mode (non-3D). Focus is on accurate visibility blocking by walls/shapes and height-aware rules.

---

## Goal
Render and validate camera FOV wedges so they respect obstacles in 2D map mode. FOV fill/outline should stop at collisions, and placement/adjustment must warn/block when FOV is obstructed. Height rules apply: walls/shapes taller than camera height block; shorter ones do not.

---

## Scope
**Included**
- Collision detection of camera FOV wedges against:
  - Walls (LineString with thickness and height)
  - Shapes (filled polygons; treat height as blocking volume)
  - Area boundaries (clamp FOV to area extents)
- Height-aware occlusion:
  - If `camera.height <= obstacle.height`, FOV is blocked by that obstacle.
  - If `camera.height > obstacle.height`, FOV passes over it.
- Visual feedback:
  - Clip/trim FOV fill/outline at intersection segments.
  - Optional “collision edge” highlighting where FOV hits an obstacle.
  - Tooltip/warning when FOV is fully or mostly occluded.
- Validation on placement and direction/FOV edits:
  - Block placement if FOV cannot project inside active area due to immediate collision.
  - Live preview shows occluded wedge while adjusting direction/FOV.

**Excluded**
- 3D frustum rendering (Phase 9/10).
- Dynamic physics/steering of people; only static occlusion for editor/preview.
- PTZ-specific behaviors beyond direction/FOV/depth.

---

## Technical Requirements
- **Geometry**: Compute FOV wedge as polygon (origin + arc). Intersect with:
  - Expanded wall polygons (thickness + height).
  - Shape polygons (height).
  - Active area polygon (for clamping).
- **Height rule**: Only consider obstacles where `obstacle.height >= camera.height`. Ignore obstacles shorter than the camera.
- **Rendering** (Mapbox):
  - Source for occluded FOV polygon.
  - Outline and fill clipped to collision result.
  - Optional collision-highlight line layer at intersection edges.
- **Placement/Editing UX**:
  - Cursor/tooltips show “FOV blocked” when obstruction occurs.
  - Prevent placement if wedge is entirely blocked or outside areas.
  - While dragging direction/FOV sliders, update occluded polygon live.
- **Performance**:
  - Use turf/intersect/lineClip; memoize per camera; throttle during drag.
  - Recompute when walls/shapes/camera props change.

---

## Deliverables
- FOV clipping engine (2D) with height-aware filtering.
- Mapbox layers for occluded FOV (fill/outline) + optional collision highlight.
- Validation hooks in camera placement and property edits (direction/FOV/depth).
- Tooltips/toasts for blocked placement or fully occluded FOV.
- Tests: unit for intersection/height logic; integration for placement blocking.

---

## Acceptance Criteria
- Cameras cannot be placed if their FOV is fully outside any area or immediately blocked by walls/shapes of greater/equal height.
- FOV rendering stops at first blocking wall/shape; does not draw through taller obstacles.
- Shorter obstacles (height < camera.height) do not clip the FOV.
- Live adjustments (direction/FOV/depth) update occlusion in real time.
- Collision highlights appear where FOV meets obstacles (or toggleable).
- Performance remains responsive during drag (no noticeable lag).

---

## Risks & Mitigations
- **Performance with many walls/shapes**: Use spatial filtering (bounds check) before intersect; throttle during drag.
- **Geometry edge cases** (grazing intersections): Add small epsilon, snap angles to avoid flicker.
- **Height data gaps**: Default missing heights to blocking (conservative) or require defaults on entities.

---

## Implementation Steps
1) Geometry utilities: build wall polygons from thickness; height-aware filter; FOV vs obstacle intersection returning clipped polygon + hit segments.
2) Source/layer wiring: add occluded FOV source; update fill/outline/edge-highlight; hook into camera render pipeline.
3) Placement/edit validation: enforce blocking/toasts; prevent save when fully occluded or outside area.
4) Live preview: integrate occlusion in camera placement cursor and property sheet sliders.
5) Tests: unit (intersection/height), integration (placement block/allow, render clipping).***
