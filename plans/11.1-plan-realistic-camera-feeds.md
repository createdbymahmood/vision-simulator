# Phase 11.1: Realistic Camera Feed Rendering

**Context:** Extends Phase 11 (Radar & Camera POV Feeds) to make each camera feed render a true point-of-view image of the full 3D scene. Feeds must show moving people, walls, shapes, and area context exactly as the camera would see them, while keeping detection overlays accurate and synchronized.

---

## Goal
Deliver fully-real POV feeds per camera by rendering the actual 3D scene from each camera's viewpoint (not a proxy or placeholder), with correct occlusion, lighting, and movement. People detection overlays must use the same visibility pipeline and remain accurate under motion.

**Note on "real camera" fidelity:** The simulator is not photorealistic (per PRD non-goals). "Real camera" here means correct perspective, occlusion, and scene contents with plausible lighting and camera optics cues, using the existing stylized materials.

---

## Scope

**Included**
- Per-camera POV rendering of the real 3D scene (walls, shapes, people, areas, ground)
- Correct occlusion and frustum culling in the feed
- Accurate motion synchronization (same timestep as main simulation)
- Bounding box overlays driven by visibility pipeline
- Feed UI updates to reflect "live" camera output quality
- Optional subtle camera optics effects (vignette, slight noise) without photorealism

**Excluded**
- Photorealistic rendering or ML inference
- Recording/export (Phase 12)
- New scene assets or textures beyond existing materials

---

## Technical Requirements

### 1) True POV Rendering
- **Per-camera render**: Use a dedicated Three.js PerspectiveCamera per camera entity.
- **Transform sync**: Position/rotation/tilt/zoom mapped 1:1 from camera entity (including PTZ changes).
- **Scene parity**: Render the *same* scene graph as the main simulation (no simplified proxy scene).
- **Visibility correctness**: Occlusion (walls/shapes/area boundaries) must match the 3D world.

### 2) Render Target Pipeline
- **Render target per feed** (or pooled targets):
  - Default: 1280x720 (configurable).
  - Dynamic scaling: 0.5x, 0.75x, 1x based on active feed count.
- **Update cadence**: 30 FPS target; drop to 15 FPS if >6 feeds active.
- **Performance**:
  - Use frustum culling + layers to limit heavy effects.
  - Optional LOD for distant objects in feeds.

### 3) Scene Composition Consistency
- **Lighting**: Same directional/ambient/hemisphere light as main view.
- **Materials**: Use existing materials; ensure consistent color space (sRGB).
- **Shadows**: Enabled for walls/people to maintain depth cues.

### 4) Detection Overlay Accuracy
- Use Phase 11 visibility pipeline for detections.
- Bounding boxes derived from the POV camera projection:
  - Project 3D person bounds into 2D feed space.
  - Clip to feed boundaries.
- Only visible (non-occluded) people get boxes.
- Detection metadata (ID, count) updated each frame.

### 5) Camera Feed UX Cues
- Each feed tile shows:
  - Live view (real scene render)
  - Camera name, resolution badge, detection count
  - Border color = camera color
- Active camera feed: thicker border + subtle glow

### 6) Optional Camera Optics (Subtle)
- **Vignette**: 5-10% darkening at corners
- **Sensor noise**: very light grain (toggleable)
- **Exposure bias**: slight brightness curve to mimic security cameras
- Must remain subtle and optional; default OFF to preserve performance

## Acceptance Criteria

- Each feed shows a *true* camera POV of the 3D world (walls, shapes, people, ground).
- People movement in feeds matches the simulation timeline without lag.
- Occlusion works: people hidden behind walls/shapes are not visible in feeds.
- Bounding boxes align with people in the feed and update continuously.
- Camera PTZ changes instantly reflect in feed view and detection results.
- Feed border colors and active state styling follow camera color rules.
- Performance remains usable with 4-6 active feeds (no stutter > 200ms).

## Risks & Mitigations

| Risk | Mitigation |
| --- | --- |
| Multi-camera rendering cost | Limit active feeds; dynamic resolution/FPS scaling |
| Bounding box jitter | Smooth projection, clamp to pixel grid |
| Visual mismatch vs main view | Share lights/materials; single scene graph |
| GPU memory pressure | Render target pooling and reuse |

---

## Implementation Steps

1) **Camera POV setup**: Map camera entities -> PerspectiveCamera instances; sync PTZ and transforms every frame.
2) **Render targets**: Create per-feed render targets; integrate rendering loop (per camera) with adaptive FPS.
3) **Feed composition**: Display render target textures in feed tiles; align aspect ratios and borders.
4) **Detection overlay**: Project person bounds; draw boxes in feed space; update counts.
5) **Performance tuning**: Add resolution scaling, feed cap, and optional optics toggles.
6) **QA checks**: Validate occlusion, motion sync, PTZ behavior, and UI styling.
